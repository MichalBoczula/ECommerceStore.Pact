# ECommerceStore.Pact

Versioned contract artifacts and compatibility history for the ECommerceStore applications.
The delivery plan is in [TECHNICAL_TODO.md](TECHNICAL_TODO.md).

## Current implementation: PACT/01-04

ASP.NET Core 10 Minimal API, MongoDB configuration and bounded readiness checks,
generated OpenAPI, ProblemDetails, local Compose and a GitHub Actions quality gate.
Immutable application versions and directed consumer/provider integrations can now be
registered and read from MongoDB. Immutable OpenAPI/Pact artifacts and publication provenance
are stored separately and downloaded byte-for-byte. Provider CI can append immutable verification
reports with structured diagnostics and retrieve their history. Compatibility selection is PACT/06;
an accepted contract upload is not a passing test.

| Endpoint | Behavior |
| --- | --- |
| `GET /health/live` | 200 when the process serves requests; does not contact MongoDB. |
| `GET /health/ready` | 200 when MongoDB responds to ping, otherwise 503. |
| `GET /openapi/v1.json` | OpenAPI generated by the application. |
| `POST /api/applications/{applicationId}/versions` | Register by full commit SHA; 201 new, 200 equivalent retry, 409 conflicting metadata. |
| `GET /api/applications/{applicationId}/versions/{commitSha}` | Read the exact registered version; 404 if absent. |
| `POST /api/integrations` | Declare a directed consumer/provider pair; 201 new, 200 equivalent retry. |
| `GET /api/integrations/{consumerApplicationId}/{providerApplicationId}` | Read a declared integration; 404 if absent. |
| `POST /api/contract-publications` | Publish a contract with registered source version and build provenance; 201 new, 200 retry, 409 conflicting content. |
| `GET /api/contract-publications/{id}` | Read a publication and its source/integration/artifact references. |
| `GET /api/artifacts/{sha256}` | Read immutable artifact metadata. |
| `GET /api/artifacts/{sha256}/content` | Download original bytes, with hash ETag and attachment filename. |
| `POST /api/verification-runs` | Append a provider CI report; 201 new execution, 200 equivalent retry, 409 changed report for the same execution. |
| `GET /api/verification-runs/{id}` | Read the original report and diagnostics. |
| `GET /api/verification-runs?consumerApplicationId=...&providerApplicationId=...&contractSha256=...` | Bounded history for an explicit integration and Pact hash; optional `limit` (1-100) and `after` cursor. |

Health responses expose dependency statuses, never connection strings or driver
exceptions. Unmatched routes return `application/problem+json` with a `traceId`.
Missing or invalid MongoDB configuration prevents startup; an unavailable database
does not prevent startup, but keeps readiness unhealthy.

Registration uses unique indexes and insert-only atomic upserts. Records retain their
original IDs and timestamps under retries/concurrency. An integration declaration does
not mean that its contract passed verification. All POSTs now require a Bearer publisher token
authorized for the target application (integration declarations are owned by their consumer).
Public reads and health require no credentials. Empty publisher configuration denies all writes.

## Register a version and integration

```bash
. ./.env
curl -i http://localhost:5080/api/applications/payments/versions \
  -H "Authorization: Bearer $PACT_PUBLISHER_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"commitSha":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","repositoryUrl":"https://github.com/MichalBoczula/ECommerceStorePayments"}'
curl -i http://localhost:5080/api/integrations \
  -H "Authorization: Bearer $PACT_PUBLISHER_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"consumerApplicationId":"payments","providerApplicationId":"invoice"}'
```

Use the actual full commit SHA in CI. IDs and SHAs are normalized to lowercase; repository
URLs use HTTPS without credentials/query/fragment. An optional `imageDigest` must have the
form `sha256:<64 hex characters>`. Version metadata is fixed at registration, including
an omitted digest. Branch/ref is publication metadata (PACT/03), not a version field.
Unknown request properties are rejected. See [ADR-0001](docs/adr/0001-registration-identities.md).

## Publish contracts

`POST /api/contract-publications` accepts this JSON envelope (replace the content placeholder
with base64 of the original file bytes):

```json
{
  "sourceApplicationId": "payments",
  "commitSha": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "kind": "ConsumerPact",
  "consumerApplicationId": "payments",
  "providerApplicationId": "invoice",
  "sourceRef": "refs/heads/main",
  "buildUrl": "https://github.com/MichalBoczula/ECommerceStorePayments/actions/runs/1",
  "contentBase64": "<base64 of original UTF-8 Pact JSON>"
}
```

Register the source version and consumer/provider integration first. For `ProviderOpenApi`,
the source application is the provider and the consumer/provider fields must be omitted.
Supported profiles are OpenAPI 3.0/3.1 JSON and Pact 3/4 HTTP with matching logical party names;
messages, plugins, external OpenAPI references and duplicate JSON property names are rejected.
The original artifact is limited to 1 MiB; the complete upload envelope to 2 MiB, also when
Content-Length is unknown. Limits return 413; bad profiles return 400; missing references 404.

Identical bytes share a hash across application versions. An immutable version/kind/integration
binding cannot change bytes, even on another branch. Each branch/build/publisher combination
has its own publication identity and timestamp. See [ADR-0002](docs/adr/0002-contract-publication.md).

Publisher tokens are configured under `RegistryAuth:Publishers:<publisher-id>` with `TokenSha256`
and an `ApplicationIds` array, e.g. `payments` for that service's CI. The local bootstrap credential
uses `*` to manage the local demo. Publisher ID comes from authentication, not the request body.
Use secret injection for token hashes in deployed configuration; keep bearer tokens in CI secrets.

## Ingest verification reports

Provider CI executes official Pact tooling and posts a normalized report using a token scoped
to the **provider** application. Register both versions and publish the consumer Pact first.
The registry validates references, coverage counts and diagnostics; it trusts authorized CI's
reported execution. Real source-repository verifier integration is PACT/08-09.

Example `POST /api/verification-runs` (replace publication ID, commits, hashes and tool version
with the exact values used by CI):

```json
{
  "consumerPublicationId": "11111111-1111-1111-1111-111111111111",
  "consumerApplicationId": "payments",
  "consumerCommitSha": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "providerApplicationId": "invoice",
  "providerCommitSha": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "contractSha256": "cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc",
  "verifierName": "pact-core",
  "verifierVersion": "<exact installed version>",
  "configurationSha256": "dddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddd",
  "ciRunId": "123",
  "ciAttempt": 1,
  "ciCheckId": "pact/orders",
  "sourceRef": "refs/heads/main",
  "buildUrl": "https://github.com/MichalBoczula/ECommerceStoreInvoice/actions/runs/123",
  "status": "Failed",
  "verifiedInteractions": 0,
  "failedInteractions": 1,
  "summary": "Missing required response field",
  "issues": [{
    "kind": "Mismatch",
    "code": "missing_body_field",
    "message": "Expected totalAmount",
    "interaction": "read an order",
    "method": "GET",
    "path": "/orders/123",
    "jsonPath": "$.body.totalAmount",
    "expected": 12.34,
    "actualPresent": false
  }],
  "evidenceUrls": [],
  "startedAt": "2026-01-01T00:00:00Z",
  "finishedAt": "2026-01-01T00:00:01Z"
}
```

`verifiedInteractions` counts successful interactions; `failedInteractions` counts mismatched
interactions. The registry derives `expectedInteractions` from the immutable Pact. Passed
requires complete success and no issues. Failed requires mismatch diagnostics. Error requires
an `ExecutionError` issue and can preserve partial mismatches. Unverified requires zero completed
interactions, no issues and a summary explaining why execution was not attempted.

A mismatch includes the Pact interaction description, HTTP operation, JSON path, expected JSON
value and `actualPresent`. For a missing value, use false and omit `actual`; for explicit JSON
null, use true and `"actual": null`. JSON numbers retain precision. Evidence URLs use HTTPS
without credentials or query parameters; log fragments are allowed. Do not publish secrets in
reports; reads are public. The complete report is limited to 1 MiB, with at most 100 issues,
10 evidence URLs and 8 KiB per expected/actual JSON value.

The same CI run + attempt + check for a version pair/binding/hash is retry-stable. A changed
report returns 409. A new run, attempt or check records another execution without replacing
history. Supply fixed original execution timestamps when retrying; do not regenerate them.
History pages use ascending record IDs, not time or compatibility priority; `nextCursor` is
passed as `after`. With concurrent inserts, restart traversal to include earlier-sorted new IDs.
See [ADR-0003](docs/adr/0003-verification-runs.md) for identities and status rules.

## Run locally

Requires Docker with Compose:

```bash
bash scripts/init-local.sh
docker compose up --build -d
curl http://localhost:5080/health/ready
curl http://localhost:5080/openapi/v1.json
docker compose down
```

The local-only stack binds API and MongoDB ports to loopback. MongoDB data is in
the `pact-mongodb` volume; `docker compose down --volumes` removes that local data.
Set `PACT_HTTP_PORT` or `PACT_MONGO_PORT` when the default ports are occupied.

To run the API on the host with .NET SDK 10:

```bash
docker compose up mongodb -d
. ./.env
RegistryAuth__Publishers__local__TokenSha256="$PACT_PUBLISHER_TOKEN_SHA256" \
RegistryAuth__Publishers__local__ApplicationIds__0='*' \
  dotnet run --project src/ECommerceStore.Pact.Api --launch-profile http
```

Development settings use `mongodb://localhost:27017`. Outside Development, set
`Mongo__ConnectionString` explicitly. Other settings are `Mongo__DatabaseName`
(default `ecommercestore-pact`) and `Mongo__TimeoutSeconds` (1-30, default 3).
The connection string is never committed with deployment credentials.

## Verification

```bash
bash scripts/verify.sh
```

The same scripts run in CI: locked restore with high/critical NuGet audit failures,
source/architecture checks, formatting, build, Domain/Application/Infrastructure/HTTP
tests, real MongoDB concurrency/index/publication tests and an authenticated Docker Compose
smoke covering immutable publication, exact-byte content retrieval and synthetic report ingestion/history.
Reports are under `artifacts/`. The integration fixture starts
MongoDB 8 through Testcontainers. Alternatively, set `PACT_TEST_MONGODB` to a local
test MongoDB connection; this does not skip the actual database check.

Container publishing and Azure deployment are PACT/07. This workflow builds and
tests the image without requiring Docker Hub credentials.

## Planned application boundaries

Consumer tests execute each application's real adapter and generated Kiota client
against Pact's mock provider. Provider verification executes the resulting Pact
against an actual provider API. CI publishes immutable artifacts and verification
evidence here. The registry determines a decision for explicit application versions;
it does not infer runtime compatibility from a schema diff alone.

The initial pilot is Payments -> Invoice. The remaining integration inventory,
including BFF registration, is in [docs/integrations.md](docs/integrations.md).
See [docs/architecture.md](docs/architecture.md) for the intended data model and
version-selection rules.
