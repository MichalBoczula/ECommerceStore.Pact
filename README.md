# ECommerceStore.Pact

Versioned contract artifacts and compatibility history for the ECommerceStore applications.
The delivery plan is in [TECHNICAL_TODO.md](TECHNICAL_TODO.md).

## Current implementation: PACT/01

ASP.NET Core 10 Minimal API, MongoDB configuration and bounded readiness checks,
generated OpenAPI, ProblemDetails, local Compose and a GitHub Actions quality gate.
This first slice exposes operational endpoints. Artifact publication, contract
verification ingestion and compatibility decisions are subsequent backlog tasks.

| Endpoint | Behavior |
| --- | --- |
| `GET /health/live` | 200 when the process serves requests; does not contact MongoDB. |
| `GET /health/ready` | 200 when MongoDB responds to ping, otherwise 503. |
| `GET /openapi/v1.json` | OpenAPI generated by the application. No business operations yet. |

Health responses expose dependency statuses, never connection strings or driver
exceptions. Unmatched routes return `application/problem+json` with a `traceId`.
Missing or invalid MongoDB configuration prevents startup; an unavailable database
does not prevent startup, but keeps readiness unhealthy.

## Run locally

Requires Docker with Compose:

```bash
docker compose up --build -d
curl http://localhost:5080/health/ready
curl http://localhost:5080/openapi/v1.json
docker compose down
```

The local-only stack binds API and MongoDB ports to loopback. MongoDB data is in
the `pact-mongodb` volume; `docker compose down --volumes` removes that local data.
Set `PACT_HTTP_PORT` or `PACT_MONGO_PORT` when the default ports are occupied.

To run the API on the host with .NET SDK 10:

```bash
docker compose up mongodb -d
dotnet run --project src/ECommerceStore.Pact.Api --launch-profile http
```

Development settings use `mongodb://localhost:27017`. Outside Development, set
`Mongo__ConnectionString` explicitly. Other settings are `Mongo__DatabaseName`
(default `ecommercestore-pact`) and `Mongo__TimeoutSeconds` (1-30, default 3).
The connection string is never committed with deployment credentials.

## Verification

```bash
bash scripts/verify.sh
```

The same scripts run in CI: locked restore with high/critical NuGet audit failures,
source checks, formatting, build, unit/HTTP tests, real MongoDB tests and a Docker
Compose smoke test. Reports are under `artifacts/`. The integration fixture starts
MongoDB 8 through Testcontainers. Alternatively, set `PACT_TEST_MONGODB` to a local
test MongoDB connection; this does not skip the actual database check.

Container publishing and Azure deployment are PACT/07. This workflow builds and
tests the image without requiring Docker Hub credentials.

## Planned application boundaries

Consumer tests execute each application's real adapter and generated Kiota client
against Pact's mock provider. Provider verification executes the resulting Pact
against an actual provider API. CI publishes immutable artifacts and verification
evidence here. The registry determines a decision for explicit application versions;
it does not infer runtime compatibility from a schema diff alone.

The initial pilot is Payments -> Invoice. The remaining integration inventory,
including BFF registration, is in [docs/integrations.md](docs/integrations.md).
See [docs/architecture.md](docs/architecture.md) for the intended data model and
version-selection rules.
